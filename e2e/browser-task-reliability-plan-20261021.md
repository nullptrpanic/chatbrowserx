# 通用浏览器批量任务可靠性 Implementation Plan

> **For agentic workers:** 使用 `superpowers:executing-plans` 逐项执行；步骤使用复选框跟踪。遵循本项目约定：单 agent，不自动提交或推送。原任务和三份手测文档准备均已通过真实验收，最终构建的完整浏览器回归 297/297 通过；不把一次通过描述为普遍稳定性。

**Goal:** 让浏览器代理正确识别操作范围、选择行内动作并核验批量任务结果，解决文档移动中的误选、重复探索和未完成即结束问题，同时保持通用性。

**Architecture:** 保留现有 observation → action → observation 和任务检查点链路。补齐观察中的结构证据与动作边界，复用现有上下文保存进度；业务完成由后续观察确认，不由点击工具猜测。测试严格区分工具机制正确与真实模型完成任务。

**Tech Stack:** 现有 TypeScript、Chrome extension/CDP、Vitest、Playwright 和共享 live runner；不增加依赖。

**Spec:** 本聊天中用户确认的方向：通用任务成功率优先，不添加网站定制逻辑；用户已要求实施，并明确验收标准为原始文档移动任务实际完成。评测执行遵循 `e2e/AGENTS.md`、`e2e/RUNBOOK.md`、`e2e/EVALUATION_STANDARD.md`。

## Global Constraints

- 不改模型、鉴权、Sandbox 或检查点存储格式；不涉及翻译功能。2026-10-21 用户已追加授权通用进度记录和结束校验，允许修改现有任务结束入口，不另建工作流引擎。
- 生产逻辑不写入网站域名、页面专用选择器、目录名称、文档 ID 或固定操作步骤。
- 保留旧工具调用和历史结果兼容性；新观察信息为可选增量，不另建浏览器工具或工作流引擎。
- 保留现有快照预算：普通 interactive 为 240 elements / 120 targets / 32000 characters，deep 为 500 / 200 / 60000；不靠扩大默认输出解决问题。
- 优先元素操作；截图仍用于确有视觉需求的情况，不以一律禁用截图换取调用数下降。
- 保留工作区已有改动，尤其不覆盖 `sandbox/src/auth.rs` 等无关修改。
- 所有可复用 E2E 实现、样本、配置与文档放在 `e2e/`；真实任务走插件和共享 runner，不通过 CLI/API 代做。
- 用户已明确授权“直接移到 IAM，逐项核验结果”：独立盘点的 26 个根级候选移入 IAM；追加授权全部核验后移回少量原候选供手测。TNS、其子项、IAM 原有子项保持不变。不修改正文或权限，不创建、复制、删除文档。

## 已有证据与问题边界

- 两份文档移入目标目录再移回的真实插件任务已成功，但存在右键、拖拽无确认后继续探索，以及同名目标选择不准确的问题。移回后原排序没有恢复，不把“恢复父目录”描述为“完全恢复原状”。
- 只读侧边栏遍历实际滚到了正确容器的上下边界，但把应排除目录的 17 个子项算入根目录候选：应为 25，回答为 42。原自动验收通过，独立业务核验失败；原始报告保留，不改写为成功。
- 当前简化观察中的 DOM depth 不等于逻辑目录层级；非标准、扁平虚拟树尤其容易混淆。
- 点击命中校验允许祖先与后代关系，并不总能区分独立子按钮。这是代码层面需要覆盖的风险，尚不能声称已证明每次误点都由它造成。
- “滚到边界后结束”的现有规则需要限定为纯读取任务。它不应终止“先遍历、再移动”的任务；目前属于规则风险，不能直接认定是全部未完成问题的唯一原因。

## Review Focus

1. 非标准扁平树、虚拟化复用节点：不能把 DOM 深度当层级，不能漏掉排除子树。由任务 1、4 覆盖。
2. 同名文档、标题旁展开按钮和更多按钮：按身份与动作区分，不按名字合并。由任务 2、4 覆盖。
3. 页面正文与侧边栏独立滚动：完成一个容器的遍历，不代表整个任务完成。由任务 3、4 覆盖。
4. 动作超时或结果不确定：先读回，不能盲目重放可能已生效的移动。由任务 3、4 覆盖。
5. 观察压缩、增量和续接：不能丢失刚补充的层级证据、范围或已验证进度；旧调用仍可用。由任务 1、3 覆盖。

## 执行顺序与验证成本

1. 先冻结失败证据和验收规则，再依次完成任务 1–3 的小范围测试；每项先失败后修复。
2. 产品候选固定后构建一次，复用同一构建跑机制 E2E：`npm run build`，随后 `npm run test:e2e:built -- --project=foreground browser-reliability.spec.ts --max-failures=1`。出现失败先诊断，不重复重建或无边界重跑。
3. 真实环境严格走 RUNBOOK 的 doctor、必要时交互 setup、standalone verify、live-run；复用已验证登录，不创建样本专用认证路径。共享真实文档串行操作；时间对比与高负载测试隔离。
4. 样本按失效机制选择，不按网站数量堆积；优先三个任务族：层级盘点、行内动作与批量移动、续接和不确定结果恢复。对照参数固定，避免每轮全量真实站点巡检。
5. 收尾只在候选稳定后运行仓库要求的门禁：`npm run format:check`、`npm run lint`、`npm run test:run`、`npm run test:e2e`、`npm run audit:bundle`、`npm run check:sandbox`、`npm run e2e:catalog:validate`。报告既有/新增失败，不弱化测试。
6. 总体是现有链路上的中等规模增强，不是重构；主要成本在非标准结构证据与严格 E2E。没有基线对比前不承诺成功率提升百分比或固定耗时降幅。
